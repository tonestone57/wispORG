# Wisp JIT and Performance Improvements Report

This document summarizes the "Just-In-Time" (JIT) and performance-related improvements identified in the Wisp codebase within the recent development history (up to commit `2d10ac92`).

## 1. QuickJS-ng Integration (Opcode Fusion & Inline Caching)

The migration to QuickJS-ng introduced several architectural performance improvements to the JavaScript engine.

### Opcode Fusion
- **Mechanism**: Frequently paired opcodes (like `get_loc 0` and `get_loc 1`) are "fused" into a single opcode (`OP_get_loc0_loc1`).
- **Benefit**: Reduces the overhead of the interpreter loop by processing multiple operations in a single dispatch step. It decreases instruction fetch and decode time for common code patterns.

### Polymorphic Inline Caching (PIC)
- **Mechanism**: Caches the results of property lookups at the call site.
- **Benefit**: Significantly speeds up property access in loops. Instead of performing a full hash table lookup or shape search every time, the engine checks if the object's "shape" matches the cached version.

## 2. Dirty Bit Incremental Layout

Implemented in commit `ac15d66f`, this is a high-level layout optimization similar to how modern browsers handle reflows.

- **Mechanism**: Introduces `DIRTY` and `CHILD_DIRTY` flags to the box tree nodes.
- **Process**:
    1. When an element changes, it is marked `DIRTY`.
    2. Its ancestors are marked `CHILD_DIRTY`.
    3. During the layout pass, the engine skips any subtrees that are not marked with either flag.
- **Benefit**: Transforms layout from a full O(N) tree traversal to a targeted update of only changed elements. This is critical for modern, dynamic web pages where small DOM changes would otherwise trigger expensive global reflows.

## 3. Fast Radix Parsing (`js_atod` Optimization)

Implemented in commit `25be346b`.

- **Mechanism**: Special-cases power-of-two bases (2, 4, 8, 16) during string-to-number conversion.
- **Benefit**: Replaces expensive multiplication and division with bit-shifting operations. This significantly improves performance for parsing hex-encoded data, which is common in large JS bundles and data-heavy applications.

## 4. Intelligent StringBuffer Memory Management

Implemented in commit `2290f6cf`.

- **Mechanism**: Implements a threshold-based shrinking strategy for `StringBuffer` objects.
- **Benefit**: Instead of keeping large allocated buffers for small resulting strings, the engine intelligently shrinks the allocation if the "slack" exceeds a certain threshold. This reduces memory fragmentation and overall heap usage during heavy string manipulation.

## 5. NaN Normalization Optimization

Implemented in commit `40219b8a`.

- **Mechanism**: Optimizes the 8-bit normalization check for NaN values in numeric index parsing.
- **Benefit**: Reduces the cost of indexing into objects/arrays when using non-standard or computed keys, which is a frequent operation in modern JS frameworks.

## 6. Concurrent QuickJS Worker Pool

Implemented in commit `cbacbbbe`.

- **Mechanism**: Introduces a hardware-concurrency-aware thread pool for executing background JavaScript tasks.
- **Benefit**: Offloads heavy JS execution from the main UI thread, preventing "jank" and improving responsiveness on multi-core systems.
